# Cognitia Adaptive Learning AL1 — Outcome-Based Learning and Feedback Specification

## 1. Executive Summary

**Adaptive Learning AL1** extends Cognitia's Adaptive Learning subsystem from inference, evaluation, and drift monitoring (AL0) into a closed-loop **Outcome / Feedback Learning Lifecycle**:

$$\text{Observation} \rightarrow \text{Representation} \rightarrow \text{Inference} \rightarrow \text{Prediction} \rightarrow \text{Outcome} \rightarrow \text{Feedback} \rightarrow \text{Learning Event} \rightarrow \text{Candidate Update} \rightarrow \text{Evaluation} \rightarrow \text{Promotion Proposal}$$

AL1 introduces strongly typed outcome and feedback contracts, candidate model lineage, deterministic parameter replay, and advisory promotion proposals while preserving Cognitia's frozen epistemic core ($E0.5-E10$) and enforcing $\text{authority} = \text{NONE}$ on all learning artifacts.

---

## 2. Core Architectural Invariants

### 2.1 Active Model Immutability
Under AL1, learning from feedback **never overwrites, replaces, or mutates the active production model in place**. Instead:
1. Historical base model parameters remain untouched.
2. An immutable `ModelCandidate` record is generated with explicit parent lineage (e.g. `laya_acoustic_v1:1.1-candidate` referencing parent `1.0.0`).
3. Candidate models are registered in `ModelRegistry` with `status = CANDIDATE` (never `ACTIVE`).

### 2.2 Strict Advisory Authority (`authority = NONE`)
Cognitia owns the **learning and advisory reasoning path**, not domain activation:
- `AdaptiveLearningResult` carries `authority = "NONE"`.
- `OutcomeRecord` and `FeedbackRecord` carry `authority = "NONE"`.
- `ModelCandidate` and `LearningUpdate` carry `authority = "NONE"`.
- `ModelPromotionProposal` carries `authority = "NONE"`.
- `PromotionDecisionRecord` captures decisions made by an external domain authority (e.g., human reviewer or governance committee), while `cognitia_authority = "NONE"`.

Cognitia can propose model updates and measure candidate performance, but **Cognitia does not autonomously deploy models, execute browser actions, alter ERP records, or control physical actuators**.

### 2.3 Epistemic Freeze ($E0.5 - E10$)
Epistemic core semantics remain completely frozen. Machine learning outputs and candidate evaluations are advisory `CognitiveObject` instances and **never automatically become Epistemic Evidence or Truth**.

## 3. The AL1 Learning Lifecycle

```text
                  HOST OBSERVATION
                         │
                         ▼
             REPRESENTATION BOUNDARY
         (Sanitized ModelInputRepresentation)
                         │
                         ▼
                     INFERENCE
              (AdaptiveLearningResult)
                         │
                         ▼
                  MEASURED OUTCOME
                   (OutcomeRecord)
                         │
                         ▼
                  FEEDBACK LINKAGE
                  (FeedbackRecord)
                         │
                         ▼
                   LEARNING EVENT
                  (LearningEvent)
                         │
                         ▼
                 CANDIDATE UPDATE
          (ModelCandidate + LearningUpdate)
                         │
                         ▼
                CANDIDATE EVALUATION
                 (ModelEvaluation)
                         │
                         ▼
                 PROMOTION PROPOSAL
              (ModelPromotionProposal)
                         │
                         ▼
             EXTERNAL GOVERNANCE REVIEW
             (PromotionDecisionRecord)
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
          ACCEPTED                REJECTED
             │                       │
             ▼                       ▼
     DOMAIN-SIDE ACTIVATION     AUDIT PRESERVATION
```

### Stage Definitions

1. **Observation**: Host domain event (e.g., acoustic sensor readings, web page state, telemetry).
2. **Representation**: Sanitized, versioned `ModelInputRepresentation` produced across the Representation Boundary.
3. **Inference (Prediction)**: Advisory result (`AdaptiveLearningResult`) generated by an `AdaptiveLearningProvider`.
4. **Outcome**: Measured ground truth or operational outcome (`OutcomeRecord`) observed by the host domain.
5. **Feedback**: Structured link (`FeedbackRecord`) linking prediction to outcome, computing error/loss metrics.
6. **Learning Event**: Immutable record (`LearningEvent`) aggregating feedback instances and data fingerprints.
7. **Candidate Update**: Deterministic parameter delta (`LearningUpdate`) and candidate model specification (`ModelCandidate`).
8. **Evaluation**: Multi-metric assessment (`ModelEvaluation`) on validation datasets.
9. **Promotion Proposal**: Factual comparison (`ModelPromotionProposal`) detailing baseline vs candidate metric deltas.
10. **External Decision**: Governance decision recorded in `PromotionDecisionRecord` without Cognitia activation.

## 4. Contracts and Provenance Lineage

All records subclass `CognitiveObject` and carry full deterministic provenance:

```python
@dataclass(frozen=True)
class ModelCandidate(CognitiveObject):
    candidate_model_id: str
    candidate_model_version: str
    parent_model_id: str
    parent_model_version: str
    provider_id: str
    provider_version: str
    status: CandidateStatus
    parameter_fingerprint: str
    parameters: dict[str, Any]
    creation_seed: int
    learning_event_ids: list[str]
    is_deterministic: bool
    authority: str = "NONE"
    provenance: ProvenanceRecord
```

Lineage guarantees:
- Every candidate model references its exact parent model ID and version.
- Every candidate captures the SHA-256 parameter fingerprint of its weights.
- Every learning update references the triggering `learning_event_id` and random seed.

---

## 5. Reference Provider (`LayaProvider`)

The reference provider `LayaProvider` (`provider_id = "laya"`) implements:
- Local-first, offline typed-decision inference.
- Deterministic candidate parameter updates (`learn(...)`).
- Candidate model evaluation (`evaluate_candidate(...)`).
- Complete isolation: base model weights are never mutated when generating candidate updates.

---

## 6. Deterministic Replay Engine (`LearningReplayEngine`)

The `LearningReplayEngine` enables verifiable historical replay:
- Re-executes candidate learning given historical `base_model`, `learning_events`, and `seed`.
- Verifies exact SHA-256 parameter fingerprint parity.
- Fails closed (`is_replayable = False`, `status = "NON_REPLAYABLE"`) when required provenance is missing.

---

## 7. Durable File Persistence (P1) Integration

AL1 stores all lifecycle records directly in Cognitia's append-only journal (`FilePersistenceService`):
- `outcome_record`
- `feedback_record`
- `learning_event`
- `learning_update`
- `model_candidate`
- `model_evaluation`
- `model_promotion_proposal`
- `promotion_decision`

During restart recovery, `EpistemicBridge` automatically re-populates all candidate models, evaluations, outcomes, and feedback without requiring a separate learning database.

---

## 8. Security & Representation Boundary

All observations, outcomes, and feedback are treated as untrusted data:
- Directives such as `"activate model immediately"` or `"rm -rf /"` are redacted by `RepresentationAdapter`.
- Credentials, bearer tokens, cookies, and secret keys are automatically stripped.
- Injected commands remain inert text data and never become executable instructions.
