# Contract: Cognitive ABI (Application Binary Interface)

**Contract Status**: Authoritative  
**Contract Version**: 1.0.0  
**Phase**: Phase 0 Foundation  

---

## 1. Purpose & Scope

The **Cognitive ABI** defines the minimal, canonical type system and data representation standards for all entities exchanged across the Cognitia ecosystem. It establishes identity, versioning, temporal representation, provenance attachment, confidence bounds, and deterministic serialization contracts.

---

## 2. Canonical Concepts

The Cognitive ABI defines a deliberately small ontology:

1. **`Observation`**: Raw or structured input recorded from a designated source.
2. **`Evidence`**: Corroborative or falsifying data backing or challenging a hypothesis/claim.
3. **`Experience`**: An episodic record linking context, observation, action, expected outcome, and actual outcome.
4. **`Hypothesis`**: A testable proposition concerning domain behavior or latent state.
5. **`Claim`**: An asserted belief or proposition with associated confidence and epistemic status.
6. **`ReasoningTrace`**: An immutable, step-by-step audit record of cognitive derivation.
7. **`Decision`**: A cognitive recommendation or proposal generated by a capability.
8. **`Action`**: A proposed or recorded operational step.
9. **`Outcome`**: An observed result or consequence following an action.
10. **`Provenance`**: The complete audit chain describing origin, producer, inputs, schema, and checksums.

---

## 3. Structural Requirements

Every canonical ABI entity MUST satisfy the following structural requirements:

### 3.1 Stable Identity (COG-001 Resolved)
* Every first-class entity MUST possess a globally unique identifier (`id`), formatted as a canonical **UUIDv4** string.
* Hierarchical URIs (e.g., `urn:cognitia:node:sensor_1`) are supported as external locators, environment IDs, or source qualifiers within entity `metadata` or `source_node` fields, but internal canonical identity is strictly UUIDv4.
* Entity identity is strictly immutable once instantiated.

### 3.2 Explicit Schema Versioning
* Every entity MUST declare a `schema_version` adhering to Semantic Versioning (`MAJOR.MINOR.PATCH`).
* Consuming adapters and services MUST reject entities with incompatible MAJOR schema versions.

### 3.3 ISO-8601 UTC Timestamps
* Every entity MUST record a creation timestamp (`created_at`) formatted in UTC ISO-8601 with microsecond precision (`YYYY-MM-DDTHH:MM:SS.ffffffZ`).
* Where a subsystem records an ingestion/acceptance event distinct from artifact creation (e.g., `ModelRecord.registered_at`), the distinction MUST be explicitly documented.

### 3.4 Provenance Attachment
* Every derived entity (`Decision`, `Evidence`, `ReasoningTrace`, `ExperienceRecord`) MUST link directly to a valid `ProvenanceRecord` detailing its creator, inputs, parent artifacts, and determinism properties.

### 3.5 Confidence Semantics (COG-007 Resolved)
* `confidence` is an advisory score normalized to the closed interval $[0.0, 1.0]$.
* The numerical score is subsystem-specific and MUST NOT automatically be interpreted as a calibrated probability, truth value, empirical certainty, or statistical significance.
* Specific semantics by subsystem:
  * **Claim**: Degree of epistemic support for the asserted claim based on available evidence.
  * **Evidence**: Evidential strength / reliability of the underlying observation(s).
  * **Decision**: Provider/capability confidence in the advisory proposed action.
  * **ReasoningStep**: Logical validity or step reliability of the deduction/derivation step.
  * **ReasoningTrace**: Aggregate inferential confidence of the derivation trace.

## 4. Deterministic Serialization Specification (COG-002 Resolved)

To support distributed event transport, offline storage, cryptographic hashing, and cross-language adapters:

1. **Format**: UTF-8 encoded canonical JSON.
2. **Key Ordering**: All object keys MUST be sorted lexicographically in ascending order.
3. **Number Formatting**: Standard IEEE 754 numeric representation formatted deterministically without trailing decimal zeros unless required by standard JSON number representation. `NaN` and `Infinity` are strictly prohibited as invalid Cognitia metrics.
4. **Whitespace**: Minimal serialization without extraneous whitespace (separators: `','` and `':'`).
5. **Determinism Guarantee**:
   $$\text{Serialize}(O, V) \equiv \text{Serialize}(O', V) \iff O = O'$$
